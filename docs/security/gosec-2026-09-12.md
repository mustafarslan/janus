## The one real finding

**`MaxRecordLen` bounded the read side and not the write side.**

`G115` flagged the `uint32(bodyLen)` conversion in
`pkg/evidence/segment/format.go`. The conversion is not itself the bug — reaching
it needs a 4 GiB record. Reading the code around it is what found the bug:
`MaxRecordLen` is checked in three places on the read path
(`format.go`, `reader.go`, `readat.go`) and **nowhere on the write path**.

`AppendRecord` framed a 64 MiB record without complaint. Reading that segment
back:

    segment: corrupt record: implausible record length 67108939 at offset 32

The segment's **first** record. Everything after it is lost too, because a reader
cannot resynchronise past a frame it does not believe. So a log this code wrote
faithfully reports as corrupt, and nothing distinguishes that from a log somebody
tampered with — in a system whose entire purpose is telling those two apart.

Reachability, stated honestly: **not reachable through `janus-orchd` today.**
Nothing overrides gRPC's 4 MiB default receive limit, so a remote caller is
stopped 16× short. Every in-process caller of `pkg/evidence` is unbounded, and
the 4 MiB bound is a default nobody chose rather than a decision anybody wrote
down.

Fixed in the same change, at two levels: the appender declines the event and
answers that one caller, and the writer refuses too. The order matters — an
`AppendRecord` failure is sticky (`ErrWritePathFailed`), so leaving it to the
writer would let one oversized payload stop the log for everybody.
`TestTheWriterRefusesWhatItsOwnReaderWouldRefuse` and
`TestAnOversizedEventIsRefusedWithoutStoppingTheLog` pin both halves.

## Every finding, triaged

| rule | n | verdict |
|---|---|---|
| `G304` file inclusion via variable | 46 | **Intended.** Every path this repository opens comes from a flag, a config field or a directory it was handed. A log tool that could only open compile-time constants would not be one. |
| `G115` integer overflow conversion | 43 | **1 real** (above). The other 42 are lengths and counters converted for the wire or for a gauge, where the source is already bounded — `len()` of a bounded buffer, a sequence number, a row count. |
| `G306` `WriteFile` perms > 0600 | 16 | **Intended.** Drill outputs, fixtures, bench JSON, corpus files. Nothing secret is written by any of them. |
| `G302` file perms > 0600 | 5 | **Intended, and narrower than the rule implies.** Segments are `0o640`: owner read-write, group read, **world nothing**. Group-readable is deliberate so a backup or audit process under the same group can read the log without being the writer. The key file is `0600`. |
| `G204` subprocess with tainted input | 4 | **Intended.** All four are `exec.Command(self, …)` — `janus-soak` and `janus-sagachaos` re-invoking their own binary to be killed, and `janus-mcpd` launching the MCP server an operator configured. |
| `G407` hardcoded IV/nonce | 3 | **False positive**, and the one worth stating. gosec matches `aead.Seal(nonce, nonce, …)` — the standard idiom for prefixing a fresh nonce to its ciphertext — and cannot see that `nonce` was just filled from `crypto/rand`. Both sites do exactly that, and `TestNonceIsFresh` already pins the property gosec is guessing about. |
| `G404` weak random | 2 | **Intended.** `cmd/janus-soak` and `cmd/janus-sagachaos` seed `math/rand` deterministically, because a chaos interleaving nobody can reproduce is not a test. Neither is anywhere near a key, a nonce or an identifier. |
| `G101` hardcoded credentials | 1 | **False positive.** `EnvSecretKey = "JANUS_S3_SECRET_KEY"` is the *name* of an environment variable. |

## What was enabled, and why not the rest

Enabling the default set would mean excluding eight rule classes to get to green
— a gate that reads as working while checking almost nothing, and one that
teaches everybody to answer it with `//nolint`. `G115`'s precision here is 1 in
43.

So `.golangci.yml` enables `gosec` with an **include list**: seventeen rules that
find **zero** today and would matter if they ever found one. No exclusions, no
suppressions, nothing to argue about in review — SQL injection (this repository
builds SQL in `pkg/projection`), weak and blocklisted crypto, TLS verification,
memory aliasing. The list is in `.golangci.yml`.

The eight noisy rules are off. They are not off *forever*: this file is what a
re-run compares against, and a rule whose findings all became intentional is a
rule worth reconsidering when the count changes.
